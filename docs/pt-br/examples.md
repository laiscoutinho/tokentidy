# Exemplos

> 🇺🇸 Para ler este arquivo em inglês, [clique aqui](../examples.md).

Execuções reais de cada comando, da primeira análise até o CI. Todas as saídas abaixo foram copiadas do TokenTidy `0.0.27`. Para o significado de cada opção, veja [Comandos](commands.md).

## De valores fixos a tokens

Um projeto pequeno:

```
shop/
├── package.json
└── src/
    ├── index.html
    ├── theme/theme.css
    └── components/
        ├── Button.tsx
        └── Card.css
```

`src/theme/theme.css` já tem um token, escrito à mão:

```css
:root {
  --brand: #4f46e5;
}
```

`src/components/Card.css` tem valores fixos, e um que a equipe quer manter:

```css
.card {
  color: #4f46e5;
  background: #FFF;
  padding: 16px;
  border-radius: 8px;
}

.card-title {
  color: #111827;
  margin-bottom: 16px;
  /* tokentidy-ignore-next-line spacing/hardcoded -- matches the print layout */
  margin-top: 13px;
}
```

`src/components/Button.tsx` tem os mesmos valores em um estilo inline:

```tsx
export function Button() {
  return <button style={{ background: 'white', padding: 16, borderRadius: 8, color: '#111827' }}>Buy</button>;
}
```

`src/index.html`:

```html
<!doctype html>
<p style="color: #111827; margin: 13px">Hello</p>
<div style="background: #fff; border-radius: 8px">Sale</div>
```

### 2. Crie os tokens

```bash
npx tokentidy generate
```

```
✔ 4 tokens saved in design-tokens/ (tokens.css).
  Next: run tokentidy fix to use them in your code.
```

O que aconteceu com cada valor:

- `#FFF`, `white` e `#fff` são a mesma cor, então viraram um token só.
- `16px` no CSS e `16` no JSX são o mesmo tamanho, assim como `8px` e `8`.
- `#4f46e5` não ganhou token novo, porque `--brand` já tem esse valor.
- `13px` não ganhou token: fora da linha ignorada, ele é usado uma vez só, e um valor precisa de 3 usos.

`design-tokens/tokens.css`:

```css
/* Generated by TokenTidy. You can edit names and values here: `tokentidy generate` keeps your changes. */
:root {
  /* color */
  --color-gray-900: #111827;
  --color-white: #ffffff;

  /* spacing */
  --spacing-4: 16px;

  /* radius */
  --radius-lg: 8px;
}
```

Você pode renomear um token ou mudar um valor neste arquivo: o próximo `generate` mantém a mudança, e o `fix` usa. Para outros formatos, adicione `--dtcg`, `--scss`, `--less`, `--ts` ou `--js` ([generate](generate.md)).

### 4. Aplique

```bash
npx tokentidy fix
```

```
1 value has no token with the same value, so it stays as written.
To also replace values close to a token, run tokentidy fix --approximate.

✔ 13 values replaced in 3 files.
  1 hardcoded value remains: run tokentidy check to see it.
  Make sure your app loads design-tokens/tokens.css (import it in the global stylesheet or add it to the build).
```

O código de saída é `1`, porque sobrou um valor: `margin: 13px`, que não tem token. **O `fix` não carrega os tokens para você:** importe `design-tokens/tokens.css` no estilo global, ou os `var()` não vão funcionar.

## SCSS: valores necessários na compilação

O Sass roda antes do navegador, então não consegue usar `var()` dentro das funções dele. Nesses lugares, o `fix` escreve a variável Sass e adiciona o import:

```scss
.a { background: darken(#4f46e5, 10%); padding: 16px; }
.b { background: #4f46e5; padding: 16px; }
```

Cada valor é usado duas vezes, e as variáveis Sass vêm do `_tokens.scss`, então gere com `npx tokentidy generate --min-occurrences 2 --scss`. Depois, o `npx tokentidy fix --dry-run` mostra:

```diff
-.a { background: darken(#4f46e5, 10%); padding: 16px; }
-.b { background: #4f46e5; padding: 16px; }
+@use '../design-tokens/tokens' as *;
+.a { background: darken($color-indigo-600, 10%); padding: var(--spacing-4); }
+.b { background: var(--color-indigo-600); padding: var(--spacing-4); }
```

## Angular: bindings e templates

```ts
@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
export class ListComponent {}
```

```html
<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
```

A unidade sai do nome do binding, porque o token já a inclui:

```diff
-<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
+<ul [style.padding]="'var(--spacing-4)'" [ngStyle]="{'margin': 'var(--spacing-4)', color: 'var(--color-gray-900)'}" style="color: var(--color-gray-900)"></ul>
```

```diff
-@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
+@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: var(--spacing-4); color: var(--color-gray-900); }` })
```

## Rodando o `generate` de novo

Quando já existem tokens, o `generate` precisa de uma decisão. Num terminal, ele pergunta. Fora de um terminal, ele para com o código de saída `2` em vez de esperar uma resposta:

```bash
npx tokentidy generate --extend   # mantém os nomes, adiciona o que é novo
npx tokentidy generate --new      # esquece os nomes gerados e recomeça
```

```
Error: Tokens generated before were found in:
  design-tokens
Use --extend to keep their names and add the new ones, or --new to start over.
```

Com `--extend`:

```
✔ 4 tokens saved in design-tokens/ (tokens.css).
  Next: run tokentidy fix to use them in your code.
```

No dia a dia, use `--extend`: os nomes que você já usa no código continuam os mesmos.

## Escolhendo limites e pastas

```bash
npx tokentidy generate --min-occurrences 2   # também valores usados só duas vezes (o padrão é 3)
npx tokentidy generate --out src/tokens      # outra pasta dentro do projeto
npx tokentidy fix --tokens src/tokens        # o fix lendo dessa pasta
```

As mesmas escolhas podem ficar no `tokentidy.config.json` ([Configuração](configuration.md)):

```json
{ "minOccurrences": 4, "gridBase": 8, "output": "tokens" }
```

Com esse arquivo, o projeto de exemplo fica com um token, para `16px`, o único valor usado 4 vezes. O `gridBase` também muda os nomes: `16px` agora é `--spacing-2`, dois passos de 8px.

## Trabalhando só em parte do projeto

```bash
npx tokentidy check src/components            # uma pasta
npx tokentidy check src/Card.css src/App.tsx  # arquivos específicos
npx tokentidy fix src/components --dry-run    # troca só aqui
```

O resultado pode ser diferente de uma execução completa: veja [Analisando parte de um projeto](check.md#analisando-parte-de-um-projeto). Para a resposta final, analise o projeto inteiro.

## Valores que são quase um token

```css
/* a.css */
:root { --space-m: 16px; }
.used { padding: var(--space-m); }
.card { padding: 15px; }
.card-b { padding: 16px; }
```

O `fix` troca o `16px`; o `15px` fica, porque não é o mesmo valor. Para ver o que o `--approximate` faria com os valores próximos, sem trocá-los:

```bash
npx tokentidy fix --approximate --no-input
```

```
.card padding: 15px ×1 → var(--space-m) (16px)
  a.css:3:18	padding: 15px → var(--space-m)	+1px
```

O `16px` exato continua sendo trocado; só o `15px` espera a sua decisão.

Num terminal, `npx tokentidy fix --approximate` mostra o mesmo grupo e pergunta `Apply? [y]es [n]o [a]ll in this group [q]uit`. A resposta fica salva no `tokentidy.decisions.json`. Mais no [fix](fix.md#valores-próximos-de-um-token---approximate).

## Usando o resultado em scripts

Os dados vão para a saída padrão e o resumo para a saída de erro, então os pipes recebem só os dados.

Contar os valores por regra:

```bash
npx tokentidy check 2>/dev/null | cut -f3 | sort | uniq -c | sort -rn
```

```
      7 color/hardcoded
      4 spacing/hardcoded
      3 radius/hardcoded
```

Listar as cores com o [`jq`](https://jqlang.org/):

```bash
npx tokentidy check --json 2>/dev/null | jq -r '.findings[] | select(.type == "color") | "\(.file):\(.line) \(.value)"'
```

```
src/components/Button.tsx:2 white
src/components/Button.tsx:2 #111827
src/components/Card.css:2 #4f46e5
src/components/Card.css:3 #FFF
src/components/Card.css:9 #111827
src/index.html:2 #111827
src/index.html:3 #fff
```

Mais em [Scripts e CI](ci-and-scripts.md) e [Saída JSON](json-output.md).
