## From hardcoded values to tokens

A small project:

```
shop/
├── package.json
└── src/
    ├── index.html
    ├── theme/theme.css
    └── components/
        ├── Button.tsx
        └── Card.css
```

`src/theme/theme.css` already has one token, written by hand:

```css
:root {
  --brand: #4f46e5;
}
```

`src/components/Card.css` has hardcoded values, and one the team wants to keep:

```css
.card {
  color: #4f46e5;
  background: #FFF;
  padding: 16px;
  border-radius: 8px;
}

.card-title {
  color: #111827;
  margin-bottom: 16px;
  /* tokentidy-ignore-next-line spacing/hardcoded -- matches the print layout */
  margin-top: 13px;
}
```

`src/components/Button.tsx` has the same values as an inline style:

```tsx
export function Button() {
  return <button style={{ background: 'white', padding: 16, borderRadius: 8, color: '#111827' }}>Buy</button>;
}
```

`src/index.html`:

```html
<!doctype html>
<p style="color: #111827; margin: 13px">Hello</p>
```

The exit code is `1`, because there are violations. Note that `margin-top: 13px` isn't listed: the comment above it keeps it on purpose.

### 2. Create the tokens

```bash
npx tokentidy generate
```

```
design-tokens/tokens.tokens.json
design-tokens/tokens.css
4 new tokens, 0 kept, 0 semantic aliases
1 values already have a token in the project:
  #4f46e5	--brand	src/theme/theme.css:2 (1 use)
1 values used fewer than 2 times were not turned into tokens
diagnosis	color	3 values, 3 tokens, 100% of uses on a token
diagnosis	spacing	2 values, 1 token, 75% of uses on a token
diagnosis	radius	1 value, 1 token, 100% of uses on a token
suggestion	spacing	13px is off the 4px grid (nearest: 12px or 16px)
```

What happened to each value:

- `#FFF` and `white` are the same color, so they became one token.
- `16px` in CSS and `16` in JSX are the same size, and so are `8px` and `8`.
- `#4f46e5` got no new token, because `--brand` already has that value.
- `13px` got no token: outside the ignored line, it is used only once.

`design-tokens/tokens.css`:

```css
/* Generated by TokenTidy from tokens.tokens.json. Edit the JSON and run `tokentidy generate` again. */
:root {
  /* color */
  --color-gray-950: #111827;
  --color-white: #ffffff;

  /* spacing */
  --spacing-4: 16px;

  /* radius */
  --radius-lg: 8px;
}
```

### 4. Apply it

```bash
npx tokentidy fix
```

```
src/components/Button.tsx
src/components/Card.css
src/index.html
11 values replaced in 3 files; 0 skipped; 1 without a token; 1 violation remains
Generated tokens are used as var(); make sure the app loads design-tokens/tokens.css (import it in the global stylesheet or add it to the build)
```

The exit code is `1`, because one violation remains: `margin: 13px`, which has no token. **`fix` doesn't load the tokens for you:** import `design-tokens/tokens.css` in your global stylesheet, or the `var()` values won't resolve.


## SCSS: values needed at build time

Sass runs before the browser, so it can't use `var()` inside its functions or in `@media`. `fix` writes the Sass variable there, and adds the import:

```scss
.a { background: darken(#4f46e5, 10%); padding: 16px; }
.b { background: #4f46e5; padding: 16px; }
@media (min-width: 768px) { .c { width: 100%; } }
@media (min-width: 768px) { .d { width: 50%; } }
```

After `npx tokentidy generate`, `npx tokentidy fix --dry-run` shows:

```diff
-.a { background: darken(#4f46e5, 10%); padding: 16px; }
-.b { background: #4f46e5; padding: 16px; }
-@media (min-width: 768px) { .c { width: 100%; } }
-@media (min-width: 768px) { .d { width: 50%; } }
+@use '../design-tokens/tokens' as *;
+.a { background: darken($color-indigo-600, 10%); padding: var(--spacing-4); }
+.b { background: var(--color-indigo-600); padding: var(--spacing-4); }
+@media (min-width: $breakpoint-md) { .c { width: 100%; } }
+@media (min-width: $breakpoint-md) { .d { width: 50%; } }
```

## Angular: bindings and templates

```ts
@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
export class ListComponent {}
```

```html
<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
```

The unit moves out of the binding name, because the token already carries it:

```diff
-<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
+<ul [style.padding]="'var(--spacing-4)'" [ngStyle]="{'margin': 'var(--spacing-4)', color: 'var(--color-gray-950)'}" style="color: var(--color-gray-950)"></ul>
```

```diff
-@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
+@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: var(--spacing-4); color: var(--color-gray-950); }` })
```

## Running `generate` again

Once tokens exist, `generate` needs a decision. Outside a terminal, it stops with exit code `2` instead of waiting for an answer:

```bash
npx tokentidy generate --extend   # keep the names, add what is new
npx tokentidy generate --new      # forget the generated names and start over
```

```
0 new tokens, 4 kept, 0 semantic aliases
```

Use `--extend` in day-to-day work: the names you already use in the code stay the same.

## Choosing thresholds and folders

```bash
npx tokentidy generate --min-occurrences 3   # only values used 3+ times
npx tokentidy generate --out src/tokens      # another folder inside the project
npx tokentidy fix --tokens src/tokens        # fix reading from that folder
```

The same choices can stay in `tokentidy.config.json` ([Configuration](configuration.md)):

```json
{ "minOccurrences": 3, "gridBase": 8, "output": "tokens" }
```

With this file, the example project gets two tokens. `gridBase` also changes the names: `16px` is now `--spacing-2`, two steps of 8px.

## Working only on part of the project

```bash
npx tokentidy check src/components            # one folder
npx tokentidy check src/Card.css src/App.tsx  # specific files
npx tokentidy fix src/components --dry-run    # replace only here
```

The result can differ from a full run: see [Analyzing part of a project](check.md#analyzing-part-of-a-project). For the final answer, analyze the whole project.

## Using the result in scripts

The data goes to the standard output, and the summary to the error output, so pipes receive only the data.

Count the values per rule:

```bash
npx tokentidy check 2>/dev/null | cut -f3 | sort | uniq -c | sort -rn
```

```
      6 color/hardcoded
      4 spacing/hardcoded
      2 radius/hardcoded
```

List the colors with [`jq`](https://jqlang.org/):

```bash
npx tokentidy check --json 2>/dev/null | jq -r '.findings[] | select(.type == "color") | "\(.file):\(.line) \(.value)"'
```

```
src/components/Button.tsx:2 white
src/components/Button.tsx:2 #111827
src/components/Card.css:2 #4f46e5
src/components/Card.css:3 #FFF
src/components/Card.css:9 #111827
src/index.html:2 #111827
```
