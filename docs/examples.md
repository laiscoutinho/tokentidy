# Examples

> 🇧🇷 To read this file in Brazilian Portuguese, [click here](pt-br/examples.md).

Real runs of each command, from the first analysis to CI. Every output below was copied from TokenTidy `0.0.27`. For what each option means, see [Commands](commands.md).

## From hardcoded values to tokens

A small project:

```
shop/
├── package.json
└── src/
    ├── index.html
    ├── theme/theme.css
    └── components/
        ├── Button.tsx
        └── Card.css
```

`src/theme/theme.css` already has one token, written by hand:

```css
:root {
  --brand: #4f46e5;
}
```

`src/components/Card.css` has hardcoded values, and one the team wants to keep:

```css
.card {
  color: #4f46e5;
  background: #FFF;
  padding: 16px;
  border-radius: 8px;
}

.card-title {
  color: #111827;
  margin-bottom: 16px;
  /* tokentidy-ignore-next-line spacing/hardcoded -- matches the print layout */
  margin-top: 13px;
}
```

`src/components/Button.tsx` has the same values as an inline style:

```tsx
export function Button() {
  return <button style={{ background: 'white', padding: 16, borderRadius: 8, color: '#111827' }}>Buy</button>;
}
```

`src/index.html`:

```html
<!doctype html>
<p style="color: #111827; margin: 13px">Hello</p>
<div style="background: #fff; border-radius: 8px">Sale</div>
```

### 2. Create the tokens

```bash
npx tokentidy generate
```

```
✔ 4 tokens saved in design-tokens/ (tokens.css).
  Next: run tokentidy fix to use them in your code.
```

What happened to each value:

- `#FFF`, `white` and `#fff` are the same color, so they became one token.
- `16px` in CSS and `16` in JSX are the same size, and so are `8px` and `8`.
- `#4f46e5` got no new token, because `--brand` already has that value.
- `13px` got no token: outside the ignored line, it is used only once, and a value needs 3 uses.

`design-tokens/tokens.css`:

```css
/* Generated by TokenTidy. You can edit names and values here: `tokentidy generate` keeps your changes. */
:root {
  /* color */
  --color-gray-900: #111827;
  --color-white: #ffffff;

  /* spacing */
  --spacing-4: 16px;

  /* radius */
  --radius-lg: 8px;
}
```

You can rename a token or change a value in this file: the next `generate` keeps it, and `fix` uses it. For other formats, add `--dtcg`, `--scss`, `--less`, `--ts` or `--js` ([generate](generate.md)).

```bash
npx tokentidy fix
```

```

✔ 13 values replaced in 3 files.
```

The exit code is `1`, because one value remains: `margin: 13px`, which has no token. **`fix` doesn't load the tokens for you:** import `design-tokens/tokens.css` in your global stylesheet, or the `var()` values won't resolve.

## SCSS: values needed at build time

Sass runs before the browser, so it can't use `var()` inside its functions. `fix` writes the Sass variable there, and adds the import:

```scss
.a { background: darken(#4f46e5, 10%); padding: 16px; }
.b { background: #4f46e5; padding: 16px; }
```

Each value is used twice, and the Sass variables come from `_tokens.scss`, so generate with `npx tokentidy generate --min-occurrences 2 --scss`. Then `npx tokentidy fix --dry-run` shows:

```diff
-.a { background: darken(#4f46e5, 10%); padding: 16px; }
-.b { background: #4f46e5; padding: 16px; }
+@use '../design-tokens/tokens' as *;
+.a { background: darken($color-indigo-600, 10%); padding: var(--spacing-4); }
+.b { background: var(--color-indigo-600); padding: var(--spacing-4); }
```

## Angular: bindings and templates

```ts
@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
export class ListComponent {}
```

```html
<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
```

The unit moves out of the binding name, because the token already carries it:

```diff
-<ul [style.padding.px]="16" [ngStyle]="{'margin.px': 16, color: '#111827'}" style="color: #111827"></ul>
+<ul [style.padding]="'var(--spacing-4)'" [ngStyle]="{'margin': 'var(--spacing-4)', color: 'var(--color-gray-900)'}" style="color: var(--color-gray-900)"></ul>
```

```diff
-@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: 16px; color: #111827; }` })
+@Component({ selector: 'app-list', templateUrl: './list.component.html', styles: `.l { gap: var(--spacing-4); color: var(--color-gray-900); }` })
```

## Running `generate` again

Once tokens exist, `generate` needs a decision. In a terminal it asks. Outside one, it stops with exit code `2` instead of waiting for an answer:

```bash
npx tokentidy generate --extend   # keep the names, add what is new
npx tokentidy generate --new      # forget the generated names and start over
```

```
Error: Tokens generated before were found in:
  design-tokens
Use --extend to keep their names and add the new ones, or --new to start over.
```

With `--extend`:

```
✔ 4 tokens saved in design-tokens/ (tokens.css).
  Next: run tokentidy fix to use them in your code.
```

Use `--extend` in day-to-day work: the names you already use in the code stay the same.

## Choosing thresholds and folders

```bash
npx tokentidy generate --min-occurrences 2   # also values used only twice (the default is 3)
npx tokentidy generate --out src/tokens      # another folder inside the project
npx tokentidy fix --tokens src/tokens        # fix reading from that folder
```

The same choices can stay in `tokentidy.config.json` ([Configuration](configuration.md)):

```json
{ "minOccurrences": 4, "gridBase": 8, "output": "tokens" }
```

With this file, the example project gets one token, for `16px`, the only value used 4 times. `gridBase` also changes the names: `16px` is now `--spacing-2`, two steps of 8px.

## Working only on part of the project

```bash
npx tokentidy check src/components            # one folder
npx tokentidy check src/Card.css src/App.tsx  # specific files
npx tokentidy fix src/components --dry-run    # replace only here
```

The result can differ from a full run: see [Analyzing part of a project](check.md#analyzing-part-of-a-project). For the final answer, analyze the whole project.

## Values that are almost a token

```css
/* a.css */
:root { --space-m: 16px; }
.used { padding: var(--space-m); }
.card { padding: 15px; }
.card-b { padding: 16px; }
```

`fix` replaces the `16px`; the `15px` stays, because it isn't the same value. To see what `--approximate` would do with the close values, without changing them:

```bash
npx tokentidy fix --approximate --no-input
```

```
.card padding: 15px ×1 → var(--space-m) (16px)
  a.css:3:18	padding: 15px → var(--space-m)	+1px
```

The exact `16px` is still replaced; only the `15px` waits for your decision.

In a terminal, `npx tokentidy fix --approximate` shows the same group and asks `Apply? [y]es [n]o [a]ll in this group [q]uit`. The answer is saved in `tokentidy.decisions.json`. More in [fix](fix.md#values-close-to-a-token---approximate).

## Using the result in scripts

The data goes to the standard output, and the summary to the error output, so pipes receive only the data.

Count the values per rule:

```bash
npx tokentidy check 2>/dev/null | cut -f3 | sort | uniq -c | sort -rn
```

```
      7 color/hardcoded
      4 spacing/hardcoded
      3 radius/hardcoded
```

List the colors with [`jq`](https://jqlang.org/):

```bash
npx tokentidy check --json 2>/dev/null | jq -r '.findings[] | select(.type == "color") | "\(.file):\(.line) \(.value)"'
```

```
src/components/Button.tsx:2 white
src/components/Button.tsx:2 #111827
src/components/Card.css:2 #4f46e5
src/components/Card.css:3 #FFF
src/components/Card.css:9 #111827
src/index.html:2 #111827
src/index.html:3 #fff
```

More in [Scripts and CI](ci-and-scripts.md) and [JSON output](json-output.md).
